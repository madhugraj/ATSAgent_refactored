# Hiring-pipeline domains — refactor findings

Scope: requisitions, candidates, matching/screening, interviews (+ pipeline core) and their UI.
Method: graph.json + domains.mjs, full import-statement scan (static + `await import`) with symbols, grep for `applications.stage` writes. Helper scripts: /tmp/ra_pipe.mjs, /tmp/ra2.mjs, /tmp/ra3.mjs; raw dumps /tmp/ra_scope.txt, /tmp/ra_syms.txt.

## 0. Headline conclusions

1. **A `pipeline` package is needed.** `lifecycle.ts` (stage state machine) + `pipeline.server.ts` (moveStageCore, addApplicationsCore, addCandidateNoteCore, assertReusable, screeningOnRecord) + `stage-events.server.ts` (recordStageTransition) + `assessment-timeline.server.ts` are used by requisitions, candidates, matching, interviews, offers, comms (nudges), org (collaboration), voice, agents, desk. Assigning them to "requisitions" is wrong — they are the application (candidate×requisition) aggregate.
2. **`.functions.ts` files double as server libraries.** `interviews.functions`, `screening.functions`, `meetings.functions`, `matching.functions`, `assessment.functions` export `*Core` functions that other server modules import. Each must split into `rpc` (createServerFn only) + `server` (cores).
3. **Domain → agents/desk upward calls are pervasive** (emitAgentEvent, agents/context, agents/runtime cancelStaleRequests/afterSubjectDeleted, agents/policy loadPolicy, agents/injection looksLikeInjection, desk.server hooks). Need an inverted event/hook port in `pipeline` (or `core/events`) that agents/desk subscribe to.
4. **Stage writes that bypass `recordStageTransition`** — `offers.functions.ts:89` (`stage:"offer_pending"`) and `:307` (`stage: data.applicationStage`) update `applications.stage` directly: no stage_events row, no agent event, no candidate email, no stale-request cancellation. `:307` also accepts the target stage from the client without `canMove`. Fix during the split: route both through `pipeline/server.moveStageCore` (system actor).
5. No UI component/route (non-API) imports server-only code in scope except a **type-only** `@db/schema` import in `ScreeningPanel.tsx` (fine). Server-only imports from `src/routes/api/public/*` are server handlers → they move to `apps/api`.

## 4. Lifecycle / stage transitions

- **State machine**: `lifecycle.ts` (FLOW, SIDE, canMove/allowedTransitions, REASON_REQUIRED, STAGE_REASONS, nextAction, stalledDays). Used by 10 UI files (StageMover, ats.tsx, LeadershipBoard, index, candidates._, interviews._, reports, screening) and server.
- **Writers of `applications.stage`** (all through `recordStageTransition` unless noted):
  - pipeline.server `moveStageCore` (HR moves; called by lifecycle.functions [step-up], nudges.functions, agents runtime/tools-phase2) — enforces canMove, HR_CONTROLLED_TARGETS, reason.
  - autoscore.server:270 (auto-advance after score)
  - matching.functions:644 (→ shortlisted)
  - interviews.functions:496, 969, 1002, 1019, 1195 (scheduled/Lx/outcome/ai_screened)
  - offer-response.server:159 (candidate accept/decline)
  - collaboration.functions:274 inserts new applications at "sourced" (insert, no event — arguably fine)
  - **offers.functions.ts:89 and :307 — direct update, NO stage event, :307 takes stage from client** ← bug/invariant gap.
- **recordStageTransition** (stage-events.server): inserts `stage_events`, enqueues screening prep (`screening_prep_jobs` on shortlist), enqueues candidate stage emails (`email-outbox.enqueueStageUpdates`), `captureFeedback` (training), `cancelStaleRequests` (agents runtime), `emitAgentStageEvents` → `emitAgentEvent` → agent orchestrator picks up events (agent_events) to start runs.
- **Agent triggering**: domain code calls `emitAgentEvent` (agents/events) directly in ~10 places (requisition approved/JD, interview scheduled/scorecard, slot chosen, transcript ready, assessment completed, stage change); orchestrator.server polls events / agent-tick cron (api/public/agent-tick) and also calls back into interviews/slot-offers/assessment-timeline (expireOffers, runAssessmentSweep).
- **Recommendation**: create `@ats/pipeline` = shared(lifecycle) + server(moveStageCore, recordStageTransition, applications aggregate cores, assessment/hiring timeline) + rpc(moveStage). Add `pipeline/server/events.ts`: `onStageChanged(handler)`, `emitDomainEvent(type,payload)`; agents, desk, comms (stage emails), training register handlers at api boot. All stage writers (incl. offers) must call `moveStageCore`/`recordStageTransition`. Domains depend on pipeline; pipeline depends only on db/core/comms-outbox port.
