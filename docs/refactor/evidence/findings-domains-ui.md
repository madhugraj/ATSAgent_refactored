### routeTree.gen.ts

Generated by `tanstackStart()` vite plugin (vite.config.ts) from src/routes. In apps/web keep `src/routes` file-based; routes become thin re-exports of feature pages. api/* routes are server routes — if apps/api is a separate server (Hono/Bun), they leave the router tree; if apps/api remains TanStack Start server functions, decide whether web and api are one deployable (server fns require same build). **Key risk:** createServerFn RPC wiring depends on the Start compiler bundling rpc modules into the same app; `rpc` entry points must be imported by apps/web and compiled there. apps/api then = HTTP handlers + workers + cron, sharing domain server packages.

### Recommended apps/web layout

```
apps/web/src/
  routes/            thin file routes (routeTree.gen.ts generated here)
  app/               AppShell, AuthGate, OrgGate, nav-config, providers, hooks (useMe/useOrg/...)
  components/        cross-feature generic (ats, pickers, LegalPage, StepUpDialog)
  features/<domain>/ components/, pages/, queries.ts (split from lib/data.ts), client utils (pdf/xlsx export)
packages/ui/         shadcn primitives, use-mobile
```
